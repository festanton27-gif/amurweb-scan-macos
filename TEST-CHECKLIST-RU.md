# AMURWEB Scan macOS 1.0.0 RC1 — финальный чек-лист перед Stable

## Статус RC1

Это функционально замороженный релиз-кандидат. Новые функции до Stable не добавляем. Исправляем только подтверждённые ошибки финального тестирования или релизной подписи.

Текущий RC1 может быть собран с ad-hoc подписью для тестирования. Публичный Stable должен быть подписан Developer ID Application и нотарифицирован Apple.

## Реальный Mac + физический сканер — обязательный Stable gate

1. Установить AMURWEB Scan из RC1 DMG в `Applications`.
2. Убедиться, что в **О программе** отображается `1.0.0 RC1`.
3. Проверить запуск на реальном Mac. Для ad-hoc RC1 разрешён запуск через **Open / Открыть** или **Open Anyway / Всё равно открыть**. Gatekeeper глобально не отключать.
4. Подключить сканер, который определяется стандартным Image Capture / «Захват изображений» macOS.
5. Нажать **Обновить сканеры**. Реальное устройство должно появиться, Mock-устройства по умолчанию отсутствуют.
6. Выполнить обычный цветной JPG-скан в 300 DPI или ближайшем реально доступном разрешении.
7. Повторить PNG.
8. Повторить обычный одностраничный PDF.
9. Проверить grayscale и B&W.
10. Проверить выбор папки Finder, сохранение файлов и последовательную нумерацию.
11. После успешного скана проверить **Показать результат в Finder**.
12. Запустить сканирование и проверить **Отменить сканирование**. Приложение и сканер должны вернуться в рабочее состояние.

## Многостраничный PDF с планшета

1. Выбрать PDF и источник **Планшет**.
2. Включить ручной многостраничный PDF.
3. Отсканировать минимум 3 страницы по одной.
4. После первых страниц выбирать **Следующая страница**.
5. После последней выбрать **Готово**.
6. Получить один PDF со всеми страницами в правильном порядке.
7. Промежуточные PNG не должны оставаться в пользовательской папке.
8. Нумерация должна увеличиться только на один итоговый PDF.
9. Повторить с источником **Автоматически**: при наличии Flatbed приложение должно выбрать планшетный путь.
10. Проверить отмену во время получения страницы и между страницами.

## Если тестовый сканер имеет ADF

1. Убедиться, что ADF отображается среди реально доступных источников.
2. Положить 2–3 листа.
3. JPG/PNG: страницы сохраняются отдельными последовательными файлами.
4. PDF: вся пачка сохраняется одним многостраничным PDF.
5. Если устройство сообщает duplex — проверить двустороннее сканирование.
6. Если duplex не поддерживается — интерфейс не должен выдавать его как рабочую возможность.

## Диагностика и session trace

1. Открыть **Справка → Диагностика сканера**.
2. Support-report должен содержать версию приложения, macOS, архитектуру, безопасные параметры сканирования и возможности устройства.
3. Постоянный scanner ID должен отображаться как `ID: redacted`.
4. В отчёте не должно быть содержимого документов, имён файлов, путей к сканам или пути папки сохранения.
5. После обновления устройств должны появиться безопасные события session trace.
6. После сканирования должны появиться события начала/завершения и количество результатов.
7. После запроса отмены должно появиться событие отмены.
8. Закрыть приложение полностью и запустить снова: trace предыдущего запуска не должен сохраняться.
9. Проверить копирование и сохранение support-report в UTF-8 TXT.

## Обновления и промо AMURWEB

1. Проверка обновлений не должна мешать запуску или сканированию при недоступном сервере.
2. Ручная команда **Проверить обновления** должна выдавать понятный результат.
3. Автоматическую проверку можно отключить, настройка сохраняется.
4. Первые 10 запусков — без промо.
5. Запуски 11–15 — промо.
6. Запуски 16–17 — без промо.
7. Далее цикл повторяется 5/2.
8. Проверить RU и EN тексты.
9. Промо и проверка обновлений не должны передавать содержимое документов.

## Developer ID + notarization — обязательный публичный Stable gate

После получения/подключения Apple Developer ID:

1. Собрать приложение с переменной `DEVELOPER_ID_APPLICATION`.
2. Убедиться, что подпись содержит `Developer ID Application` и Hardened Runtime.
3. Настроить профиль `notarytool` в Keychain.
4. Запустить `scripts/notarize-release.sh`.
5. `notarytool submit --wait` должен завершиться успешно.
6. `stapler validate` должен пройти успешно.
7. Gatekeeper-проверка `spctl` должна принять готовый DMG.
8. После notarization пересчитать и опубликовать финальный SHA-256.

## Что вернуть разработчику после аппаратного теста

- модель Mac и версию macOS;
- модель сканера и тип подключения;
- пройденные/непройденные пункты этого чек-листа;
- сохранённый support-report после теста;
- точный текст любой ошибки;
- по возможности скриншот окна программы при ошибке.

Если обязательные аппаратные пункты и Developer ID/notarization проходят без критических ошибок, RC1 переводится в **AMURWEB Scan macOS 1.0.0 Stable** без добавления новых функций.
